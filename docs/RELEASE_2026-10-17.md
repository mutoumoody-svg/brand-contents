# Studio Release 2026.10.17

## Deployment boundaries

- Push source code to GitHub; never upload `brand.env`, `.env`, backups, database, `work/brand-memory.json` or user exports.
- Keep production's existing database and AI/mail configuration. Local official Anthropic direct access was verified, but this does not prove the China-hosted server can connect directly. Preserve the existing Worker configuration on the server until it is independently tested.
- The local preview login route requires explicit opt-in, loopback address, localhost host and matching Origin. It is disabled in production. Restart production with `NODE_ENV=production LOCAL_PREVIEW_AUTH_BYPASS=0`.
- `/` and login now lead to `/studio.html`; the old workbench is retained as an advanced tool.

## Server procedure

Create a server/database/config backup first. Do not overwrite the server database with the local preview database.

```bash
cd /var/www/brand-contents
git status --short
git fetch origin
git merge --ff-only origin/main
npm ci
npm run check
npm test
npm audit --omit=dev
NODE_ENV=production LOCAL_PREVIEW_AUTH_BYPASS=0 pm2 restart brand-contents --update-env
curl --fail http://127.0.0.1:3000/api/health
node scripts/verify-ai.js
```

Stop on any failure. Do not use `git reset --hard`, `git clean` or `npm audit fix --force`. If SSH/GitHub is unavailable, use a verified Git bundle with the same fast-forward merge and verification steps. A GitHub push alone does not deploy the server.

Verify the production release/revision externally, confirm preview session endpoint returns 404, then log in and test a short batch, analysis and a directed rewrite. The returned health revision must match the intended release commit.
