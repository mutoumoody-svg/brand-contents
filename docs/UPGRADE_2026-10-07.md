# 内容工作台升级

## 使用

- `/workspace.html`：创作任务、历史查重、方法反馈、管理员运行状态。
- 小红书文案页提交后进入工作台；服务器保存任务和每篇结果，关闭网页不会停止生成。
- 重启服务后，未完成任务变为暂停，可以继续生成。单篇失败可单独重试。
- 每篇可修改、采用、保存到内容库、复制；整批导出为文本。
- 手工发布后填入链接、点赞、评论、收藏与修改反馈。方法反馈按当前用户统计，多方法同时使用时每个方法都会计入，不代表单个方法的因果效果。
- 人工反馈会进入后续同品牌生成上下文；这是资料检索与提示词应用，不是模型参数训练。
- 左侧检查按钮可打开真实开关和手动查重。已有页面的生成请求接入服务端历史检查；结构分析及策略JSON请求不自动重写，以免改变分析结果。检测以文字重合为主，不保证风格完全不同。

## 运行配置

主服务读取 `.env`，然后读取 `brand.env`（后者优先）。密钥不要提交。
代理模式配置 `CLAUDE_PROXY_URL` 和 `CLAUDE_WORKER_SECRET`，API Key由Worker保管；直接调用模式则使用 `ANTHROPIC_API_KEY`。
管理员运行状态只显示配置是否存在，并非实际连通验证。
没有配置安全的JWT密钥时，会在受保护的data目录创建随机持久化密钥；旧默认密钥签发的登录需重新登录。
仅允许公开页面与assets目录访问，数据库、环境文件及源代码不作为静态资源提供。

## 服务器更新

先在Windows终端执行 `ssh ubuntu@122.51.255.195`，进入Ubuntu后运行：

```bash
cd /var/www/brand-contents
bash scripts/deploy.sh
```

新脚本首次尚未下载时先运行 `git fetch origin` 与 `git merge --ff-only origin/main`。
脚本备份数据库和环境文件，再快进更新、安装依赖、检查、重启PM2。
Git提示本地修改或权限问题时，先检查差异与所有权，不要直接reset/clean。
建议Node 22或24 LTS，实际启动需验证better-sqlite3原生模块。
`/api/health`显示发布版本与Git提交。

## 边界

单进程PM2执行任务；不要使用cluster多实例，否则需跨进程锁。
同品牌历史最多比较150条内容库记录及150条草稿。
此外比较最近100次已接入检查的生成结果；未指定品牌的内容在同一历史池比较。
暂停在当前篇调用完成后生效；中断的篇重试可能产生额外API费用。
发布指标人工回填，没有自动拉取小红书数据。
